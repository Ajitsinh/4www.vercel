DNS - Domain Name Service

What does DNS, Domain Name Service, do for us? As the acronym implies,
it provides naming information about our domains, including tidbits
like Mail Server (MX) records, name-to-IP resolution (A or CNAME
records) or reverse lookups from IP address-to-name resolution (PTR
records). You can even obtain info on the host computer or operating
system (H record)!

At a more fundamental level, the Internet works in IP addresses, with
routers directing traffic to and from these virtual locations. By the
way, routers don't like domain names. People, on the other hand, don't
like IP addresses. Just looking at them makes people nervous. More
importantly, which are you going to remember better in your head?

  http://64.39.31.27

or

  http://www.dns.net

For most people (and companies that use domain names for marketing),
the latter would be more agreeable. Thus, DNS servers were invented to
translate between domain names and IP addresses. When you visit a Web
site, like the one above, your machine has settings to indicate which
DNS server(s) you want to use. Generally, they'll be your company's or
ISP's servers. These systems receive your requests and look things up
from there.

If they already have the information in their cache, perhaps from
recent lookups, then they'll return you the appropriate Web page
immediately. But if they don't, they'll refer to someone else with
authority. This is called a recursive lookup. A root DNS server might
be contacted first, or some server that knows about ".net" addresses.
It would return information (NS records) of where the specific DNS
server for "dns.net" is.

Now your DNS server at least knows where to get better information. So,
a request goes out to the DNS server for "dns.net" and looks for an A
record for the host "www." The returned response will include the IP
address information for that host. This information is then returned to
your machine, and a packet is sent out over the Internet with a
destination IP address of "64.39.31.27," which is something all routers
understand.

Now, looking at this method of conversation, let's go back to the
question you asked.  Since these things work for devices all over the
Internet, is there anything really location-specific to its existence?

Now, I'm sure that everyone's DNS server (or other filters) can
prohibit groups/addresses from using their DNS server, but DNS by
itself is a fairly open protocol, so there's no reason that one DNS
server shouldn't be able to serve multiple VLANs. Watch your
utilization level, though! If you have too many users, having more than
one server might be the way to go. Redundancy is sometimes a good
thing!
